## Event 服务把事件变成读模型

Kafka 把 `seckill.events` 交给 `EventProjector.onEvent`。它按事件类型更新两处：

| 事件 | Redis | Elasticsearch |
|------|-------|----------------|
| `PromotionStartEvent` | 放进正在进行的活动 | 写入活动文档 |
| `CouponGrabbedEvent` | 记下这张券，并挂到该用户名下 | 写入券文档，id 为 `promotionId:customerId` |
| `PromotionFinishEvent` | 从正在进行的活动里去掉 | 标成已结束 |

Query 服务不消费 Kafka。它只读 Event 已经写好的 Redis。所以链路是：

```text
PostgreSQL 事件 → outbox → Kafka → EventProjector → Redis
                                                      ↑
浏览器 → nginx → Gateway → Query ————————————————————┘
```

`SeckillQueryRestController` 的三个 GET：

| 方法 | 路径 | 数据从哪来 |
|------|------|------------|
| `queryCurrent` | `GET /query/promotions` | Redis 中的活动 |
| `querySuccess` | `GET /query/coupons/{customerId}` | Redis 中该用户的券 |
| `search` | `GET /query/coupons/search` | Elasticsearch |

路径参数 `{customerId}` 用 `@PathVariable`。搜索的 `customerId`、`promotionId` 用 `@RequestParam`，因为它们出现在 `?` 后面，而且可以不传。

## 回放

读模型可以重建，因为事实在 PostgreSQL 的事件表里。`ReplayController` 提供：

```text
POST /admin/replay?promotionId=...&fromSeq=0
```

这个接口在 **Event 服务的 8084** 上，不经过 Gateway，nginx 也没有代理它。`fromSeq` 默认 0，表示从这条活动的开头重放。`EventProjector.replay` 按序号把事件再投影一遍。

投影失败的消息会进入死信主题 `seckill.events.dlt`。第一遍只要知道有这个去处，不必先读消费者的错误处理分支。
